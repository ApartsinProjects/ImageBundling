# Fable brainstorm: improvements to atlasing and encoding (2026-08-28)

Generated by a Fable agent given the full set of measured findings. Prioritized ideas
memo; effect guesses are hypotheses, not measurements. Top-5 "do next" at the end.

## Top 5 do-next (agent's ranking)
1. **Shared-tables JPEG byte-bundle** (JPEG abbreviated format: one DQT+DHT tables
   datastream + N tables-less scans). Captures JPEG's entire atlas win (amortizing
   ~600 B/file of tables) with ZERO atlas downside: no quality coupling, no
   whole-atlas decode/memory. Should dominate the JPEG atlas at every tile size,
   including 224px photos where the atlas win had decayed to +3%. Few hours.
2. **Animated-WebP-as-container** (one tile per ANMF frame): each frame keeps its own
   VP8 entropy tables and 4 quantizer segments inside ONE file/request, removing the
   exact mechanism that makes WebP-on-photos go negative. Frames can differ in size
   (solves mixed-size packing). Decode via ImageDecoder (Chromium); Safari fallback to
   byte-bundle. Most likely genuinely-new result; could flip the -8.5% at 224px.
3. **Streaming progressive decode of the byte-bundle** (ReadableStream + ImageDecoder,
   tiles priority-ordered): individual-image-like progressive reveal with
   single-request transport. Attacks the two remaining transport weaknesses at once
   (HTTP/2 parity, packet-loss fragility); any received prefix is usable, so chunking
   becomes unnecessary.
4. **Append-only bundle layout for delta updates**: delta cost is proportional to
   changed bytes only if layout is stable; append-only (append new/changed tiles,
   update index) keeps Brotli-with-dictionary deltas tiny under churn. Turns the
   delta number into a design law.
5. **Decoded-memory accounting**: measure real renderer memory (atlas 64 MB RGBA for a
   4096px atlas that is 300 KB on the wire) vs byte-bundle (per-tile decode + discard).
   The paper's missing cost column; also the honesty check on large-atlas advice.

## Other notable ideas
- Bundle-optimized global Huffman tables (pooled two-pass); k-clustered DQT families
  for JPEG (analog of the WebP-segment story).
- WebP near-lossless for flat art (VP8L + LZ color cache, inherits the duplicate-dedup
  win); document that the 4-segment ceiling is knob-immune.
- PNG filter-run layout (generalize the vertical-strip win: pack columns of
  filter-behavior-similar tiles); shared-palette PLTE/tRNS icon atlas (classic sprite
  trick, +20-40% when pooled palette <=256 colors -> becomes a packing criterion).
- JPEG restart markers as a random-access index (enables Range fetch + partial decode).
- Per-tile vs per-bundle chroma subsampling penalty (JPEG analog of segment starvation).
- Alpha-plane separation: JPEG color atlas + PNG-gray alpha atlas for lossy icons with
  alpha (40-70% vs PNG-only; old trick, big number).
- Codec-aware bundle partitioner (the capstone optimizer: never form a bad bundle).
- Priority/above-the-fold sub-bundle first; range-requests-into-bundle honesty check
  ("you download 500 to show 30"); service-worker assembly (keeps plain <img> markup).
- HTTP/2 reframe: on h2 bundle for CACHE granularity and CDN request pricing and
  revalidation storms (500 If-None-Match -> 1), not for wire speed. Measurable via the
  304 path.
- Reframe (the paper's theory): a coupling spectrum, what do tiles share, transport ->
  container -> tables -> entropy state -> quantizers -> pixels? Savings come from
  sharing FIXED costs; losses come from sharing ADAPTIVE state. Every measured number
  is a point on that curve. SVG sprite as the flat-art boundary marker.
